## 1. 다음 세션 시작 체크리스트

1. `git status -sb` 로 `main...origin/main` 일치 확인, `git config --local --list` 로 이 저장소 전용 설정(커밋 이메일·`sknskin` 인증 도우미) 확인
2. Docker Desktop 실행 → `npx supabase start` → `npx supabase test db` (127 통과 기대)
3. `npm test` 결과는 **`Test Suites:` 줄까지** 확인 (Tests 줄만 보면 실패 스위트를 놓칠 수 있음)
4. `npm run web` → http://localhost:8081 (화면 변경이 반영되지 않으면 `npx expo start --web --clear` 로 재시작 — 이 환경은 watchman 미설치로 파일 감지 누락 사례 있음)
5. 로컬 데모 계정은 로컬 DB 에만 존재. 필요하면 앱에서 새로 가입

## 3. 알려진 미검증·한계

- DST 경계 날짜 계산 미검증 (Asia/Seoul 은 DST 없음).
- 백업 복원 후 `reapply_account_deletions()` 결합 시나리오 미실행.
- 비밀번호 재설정·가입 인증 링크는 PKCE 방식이라 **요청한 같은 기기**에서 열어야 함.
- 탈퇴자의 완료일 기준 열린 회차·개별 변경 회차는 순번 첫 사람에게 재배정 (리뷰어 수용 판단).
- `npm audit` 경고는 Expo SDK 의존성 유래, `--force` 수정 금지.

## 4. 작업 규칙 (이 저장소)

- 커밋·푸시는 사용자 요청 시에만. 항목별로 잘게 나누고 메시지는 한 줄, AI 관련 태그 없음.
- Git/GitHub 은 개인 계정(`sknskin`)만. 이 저장소 로컬 설정으로 인증하며 **전역 활성 gh 계정은 바꾸지 않는다**. 회사 계정·회사 정보는 공개 저장소에 쓰지 않는다.
- 스키마 변경은 새 마이그레이션 파일로만 (이미 원격에 적용된 뒤에는 기존 파일 수정 금지). 원격 대시보드에서 직접 스키마 수정 금지.
- 자동 테스트·동시성 스크립트는 로컬 DB 전용.
- 큰 변경 후에는 별도 리뷰 에이전트로 독립 검토, 지적 사항 반영 후 재검토.
