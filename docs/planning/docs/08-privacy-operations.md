# 개인정보·계정 탈퇴·백업·운영 정책

## 최소 수집

인증 식별자, 닉네임, 공간 멤버십, 루틴·완료 기록, 필요한 푸시 토큰/설정만 수집. 나이·성별·상세 주소·연락처 일괄 접근·정밀 위치·광고 식별자 등은 기본적으로 요구하지 않음. 활동 기록은 거주 생활 패턴을 추정할 수 있으므로 민감하게 취급.

## 계정 삭제 vs 공간 탈퇴 vs 공간 삭제

- 공간 탈퇴: 그 공간 데이터 조회/변경 권한 즉시 해제; 남은 공간은 영향 없음. 미래 담당 회차는 재배정 필요 처리. 관리자가 유일하면 권한 이전/공간 정리 선행(권장 초안).
- 공간 삭제: 관리자 권한과 영향 안내, 유예·복구 정책 설계; 다른 공간에는 영향 없고 법적 보존/삭제 정책 따름.
- 계정 삭제: 재인증, Auth·개인 설정·기기 토큰 처리, 개인 공간 삭제, 공유 이력 최소 보존·재식별 위험 검토. 공동 완료 기록/메시지에 동일 규칙을 기계적으로 적용하지 말 것.
- 앱스토어 출시 이전에는 플랫폼 요구 계정 삭제 경로 및 외부 삭제 요청 경로를 확인·구현.

## 개인정보 삭제 및 복원

공동생활 공간에서는 단순 `user_id=NULL`만으로 익명화 보장 안 됨. 그룹 규모·자유 입력 메시지·시간대 등으로 재식별 가능. 보존 법적 근거가 없으면 삭제/강한 비식별 처리. 백업에 삭제 이전 레코드가 남을 수 있으므로 삭제 요청 이력과 복원 후 재삭제 절차 필요. 보존 기간/법률 준수는 배포 국가 및 실제 운영 정책에 따라 검토 후 확정.

## 권장 초안 백업

매일 1회 DB 논리 백업, 외부 암호화 저장소에 최근 14일 보존, 월 1회 격리 환경 복원 테스트, 실패 경보. **이 수치는 합의된 검토 가능한 초기값**. Supabase Free 백업 기능, DB 백업 범위, Auth/스토리지 별도 복원 여부, 비용·저장소/암호 키는 착수 전에 재검증. 저장소 Git에 백업 원문 업로드 금지.

## 보안 운영

최소권한/RLS/서버 검증, API키·개인토큰 보호, 로그인 오류·DB용량·알림 실패·Cron 누락·백업 상태 감시. 로그에 PII·요청 토큰·감사 본문 원문 남기지 않음. 유료 인프라 사용, 운영 데이터 삭제, 데이터 추출, 공개 배포, 외부 Slack/메일 발송은 권한·승인 확인 필수.

## 환경 분리

개발 로컬/클라우드와 내부 베타용 Supabase 프로젝트를 분리하며 test/live 키 혼동을 방지. 자동 마이그레이션은 검증 환경에서 재현 후 승인된 대상에 적용. 운영 계정/프로덕션은 내부 베타 이후 별도 검토.
