# 모바일 디자인 시스템 — Soft Native

## 원칙

미니멀·따뜻함·자연스러운 OS 관행. 기존 레퍼런스의 부드러운 인상을 유지하되 귀여운 일러스트에 의존하지 않는다. 생산성 앱의 가독성과 생활 기록의 정서적 온도를 결합한다.

## 제안 디자인 토큰 (초안, 확정 컬러 시스템 아님)

| 토큰 | 라이트 예시 | 사용 |
|---|---|---|
| background | `#FAFAF8` | 전체 바탕 |
| surface | `#FFFFFF` | 카드·시트 |
| text-primary | `#292F2B` | 제목/본문 |
| accent | `#374D43` | 주요 버튼/선택 |
| accent-soft | `#A8BAAD` | 보조 표현 |
| divider | `#EFEDE7` | 경계선 |

다크 모드는 단순 색상 반전이 아니라 독립 semantic tokens로 구성하며 기본은 OS 시스템 설정을 따른다. 색으로만 완료/오류 상태를 전달하지 않는다. 토큰별 대비는 실제 개발 시 측정.

## 컴포넌트

- `RoutineRow`: 목록 밀도 우선, 체크 상태, 담당자, 예정 시각, 미완료 상태.
- `SpaceSwitcher`: 공간 전환 및 공간별 캐시 초기화/로딩.
- `RoutineEditor`: 반복 모드·담당·알림·현재/미래 적용 범위.
- `CompletionFeedback`: 짧은 모션·최소 햅틱·취소 가능 상태.
- `TimelineEvent`: 실제 수행자, 기록 시각, 감사 반응.
- `BottomSheet`, `NoticeBanner`, `EmptyState`, `ErrorState`, `InvitePreview`, `ConflictDialog`.

## 모션/네이티브

완료 피드백 목표 150~250ms의 짧은 전환(권장 예시, 실제 접근성/성능 테스트로 조정), 햅틱은 사용자 환경·OS 허용 범위 내에서 제한적 사용. 과도한 축하 팝업 없음. iOS/Android 공통 화면 계층을 유지하되 뒤로 가기, 날짜 선택, 권한 요청, 알림, 키보드 동작은 플랫폼 관행 적용. Reduce Motion 준수.

## 화면별 시각 우선순위

홈: 현재 해야 할 일 → 필요한 요청/미완료 → 오늘의 완료 → 최근 활동. 캘린더: 일정과 과거 기록 날짜 구분. 루틴: 설정과 주기 미리보기. 기록: 사람·수행·감사 흐름. 제휴 상품은 MVP 제외, 향후 필요한 맥락에만.

## 레퍼런스와의 차이

초기 이미지의 가사 분담, 완료, 상대 반응, 따뜻한 톤은 참조하되, 특정 이미지 속 이름·일러스트·샘플 일시·메뉴 개수는 요구사항으로 확정하지 않음. 최종 탭은 대화에서 확정한 4개를 따른다.
