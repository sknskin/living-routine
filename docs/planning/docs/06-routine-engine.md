# 반복 루틴 엔진·상태 전이 상세 명세

## 1. 반복 모드

1. `fixed`: 공간 기준 현지 달력 날짜/요일에 일정 생성. 지난 회차 미완료여도 다음 회차 생성, **회차 순서**로 교대.
2. `after_resolution`: 마지막 실제 완료 또는 건너뛴 날(건너뛰기는 완료 통계에서 제외)을 기준으로 N개의 공간 달력 날짜 후 다음 회차 생성. **정상적으로 해결된 회차 뒤** 담당 교대.
3. `manual`: 필요할 때 실행, 하루 여러 번 독립 회차 생성. **유효한 실행 회차별** 교대. 동시에 수동 실행하면 동일 동작의 재시도인지 독립 실행인지 request_id/명시적 실행으로 구분.

'7일 후'는 추천안으로 **공간 날짜 달력의 +7일**, 168시간 고정 간격이 아님. DST 세부 부재·중복 시각은 최종 테스트 전 명시적인 정책 검증 필요.

## 2. 회차 상태

`scheduled → due → completed` 또는 `skipped`; 기한 경과로 `overdue` 표시 가능하나 미완료 회차를 자동 건너뛰지 않음. `completed → undone`은 검증된 취소 이벤트를 통해 이루어짐. 내부 상태로 별도 `conflicted`, `archived`가 필요할 수 있으나 UI 표시 상태와 DB 상태는 구별.

- 고정 반복에서 오래된 `overdue`는 별도 보관·조회, 홈은 현재 회차 중심.
- 완료 시 `original_assignee_id`, `performer_id`, `recorded_by` 기록; 직접 확정/권장 초안의 경계는 `00-decision-register.md` 참조.
- `completed`를 취소할 때 후속 회차 수정·완료·도움 수락 등 영향이 있으면 원복 금지하고 충돌/검토로 반환.
- 건너뛰기는 통계에서 완료로 간주하지 않음.
- 동일 회차 완료 경합은 DB에서 **최초 유효 확정**을 승자로 처리; 나중 요청이 수행자를 덮어쓰지 않는다.

## 3. 미래 회차 생성

최근 미래 창(예: 30일)은 **제안 수치**, 무제한 생성하지 않음. 먼 미래는 미리보기 계산. 이미 존재하는 동일 회차/버전의 반복 생성 금지(고유 인덱스 또는 멱등 키). 시간대 변화와 규칙 변경에 대응하도록 preview와 materialize는 동일 계산 코어 사용.

## 4. 규칙 변경

사용자가 주기를 바꾸면 현재 회차는 기본 보존, 사용자 선택으로만 변경. 과거 사건·개별 변경된 미래 회차는 보존; **일반 미래 회차만** 새 규칙으로 재계산. 서버 함수 한 트랜잭션 안에서 루틴 버전과 미래 회차를 갱신. 예약 알림도 변경된 예정일에 맞춰 재계산. 후속 완료 이력과 충돌하면 자동 삭제/재배치 금지.

## 5. 월말 및 시간대

'매월 31일'인데 존재하지 않는 달은 그 달 마지막 날 사용. 공간 IANA timezone으로 기준 날짜/요일 계산, 사건 시각은 UTC로 저장. 완료 후 N일과 달력상 반복은 공간 날짜 규칙으로 정의. 개인 수신 시간·DND는 개인 알림 설정; 같은 공간의 예정일은 같아야 한다.

## 6. 담당·도움 요청

- 고정·교대·자율 세 모드. 교대 순서에는 탈퇴 회원이 포함되면 안 되고 재배정 필요 상태로 전환.
- 미완료 자동 타인 전가 금지, 요청 수락 전 기존 담당 유지.
- **권장 초안**: 공간 구성원이 직접 수행했다면 타인 담당 회차를 대신 완료할 수 있지만 담당 교대 순서를 바꾸지 않음. MVP에서 남의 실제 수행을 대신 등록하는 행위는 제한; 본인 기록 직접 정정, 타인 기록은 요청.
- 수동 교대에서 완료 취소로 과거 순서가 바뀌더라도 이미 후속 실행이 진행된 경우 자동 재작성 금지.

## 7. 경합/복구 시나리오

| 상황 | 안전한 기본 처리 |
|---|---|
| 동일 회차 두 기기 완료 | 한 요청만 성공, 나머지는 ALREADY_RESOLVED+재조회 |
| 완료와 건너뛰기 동시 | 서버 확정 순서 우선, 뒤 요청 실패 |
| 취소와 다음 회차 수행 | 후속 영향이 있으면 CONFLICT_VERSION/영향 안내 |
| 담당자 변경과 완료 동시 | 트랜잭션/버전 검증, 최신 담당/허용 수행자 정책 판단 |
| 기존 미래 회차 개별 수정 | 루틴 규칙 변경에서 그 회차 제외 |
| 과거 고정 회차 늦은 완료 | 원래 예정일·실제 수행일 별도; 후속 확정 순서 불변 |
| 완료일 기준 회차 건너뛰기 | 건너뛴 날짜부터 새 간격, 완료 이력에 미포함 |

## 필수 성질 테스트

- 동일 입력·동일 규칙 버전은 같은 예정 날짜를 생성.
- 하나의 회차가 중복 완료되지 않음.
- 취소가 과거 이벤트 원문을 지우지 않음.
- 월말·윤년·DST 경계 검증.
- 공간 간 루틴/담당/완료 교차 참조가 불가능.
- 규칙 버전 변경 시 완료된 과거 기록은 불변.
