# MVP 개발 로드맵과 작업 체계

## 원칙

수직 슬라이스: 기능 하나를 DB·서버·UI·테스트까지 묶어 완료. UX만 먼저 전부 제작하거나 BO 전체를 완성한 뒤 FO를 시작하는 방식이 아님. 데이터 계약은 먼저 합의, 독립 기능은 병렬 개발 허용. MVP에 장보기/소모품·제휴·구독 결제를 넣지 않음.

## 사이클 구성(제안)

| Cycle | 목표 | 완료 기준 |
|---|---|---|
| C00 기반 | Expo/Supabase 개발·베타 환경·하네스·CI·마이그레이션 | 각 환경 빌드, 테스트 명령, 환경 비밀값 격리 |
| C01 개인 루틴 | 인증·온보딩·추천·세 반복 모드·완료/취소 | 혼자 1회 이상 반복 이용, 서버 상태/테스트 일치 |
| C02 공동생활 | 복수 공간·초대/RLS·담당/교대·도움·동시 변경 | 두 계정 두 기기 및 RLS 경계 테스트 |
| C03 화면 UX | 4탭·캘린더·타임라인·반응·소프트 네이티브 | 화면 E2E, 다크·접근성/실기기 확인 |
| C04 알림·운영 | 요약/개별/재알림·DND·푸시·백업/탈퇴 | 예약/오류/복구/RLS 검증 |
| C05 베타 | 4~8명 약 2주 사용·버그 수정 | 심각 결함 해소, 결과/미결정 보고 |

## Task → Bucket → Cycle → Full Cycle

- Task: 목표, 담당자, 입력/출력, 완료기준, 검증 증거.
- Bucket: 관련 Task 묶음, 팀 책임과 선행의존성.
- Cycle: 관련 Bucket과 통합 검증.
- Full Cycle: 승인된 MVP 대상 전체 Cycle.
- 상태: backlog / ready / in-progress / blocked / implemented / tested / verified / done. 단독 구현만으로 done 금지.

## 예시 작업 분해

`C02-B03-T01` 초대 토큰·만료 DB, `T02` 수락 RPC+권한, `T03` Expo 초대 수락 화면, `T04` RLS/경합 테스트, `T05` 독립 QA. 동일 파일·DB 마이그레이션 동시 편집 금지. 팀/에이전트 인원과 모델은 실제 기능·가용량 기준 동적 할당.

## 규모·일정

과거 12~18주 예상은 **주 15~20시간 투입하는 숙련 개발자 1명+AI 보조**라는 가정 기반의 비보장 추정. 실제 개발자 수, 경험, 외부 계정, 세부 앱스토어 정책 확인 후 다시 산정.

## 릴리스 게이트

- Gate 0: 최종 직접 확정/초안/보류 분류와 환경 권한 확인.
- Gate 1: 마이그레이션/서버 테스트 재현.
- Gate 2: 핵심 사용자 여정 자동/수동 확인.
- Gate 3: 실제 iOS·Android 기기 알림·인증·UX 검증.
- Gate 4: 보안/백업·계정삭제·고장 복구 검증.
- Gate 5: 베타 피드백 반영 및 출시 판단.

## 착수 조건

**현재는 기획 산출물만 작성.** 실제 개발은 사용자 명시 승인 이후 수행. 착수 시 저장소 존재/브랜치·Git 상태, CLI 권한, 소셜 인증 제공자, Supabase 프로젝트, 미확정 오프라인 정책이 해당 작업에 영향을 주는지 확인.
