# 의사결정 레지스터 및 우선순위

## 규칙

- `USER-CONFIRMED`: 사용자가 직접 선택한 정책. 임의 변경 금지.
- `RECOMMENDED-DRAFT`: 후속 기획을 권장안으로 일괄 진행하라는 지시에 따라 채택된 **수정 가능한 초안**.
- `ON-HOLD`: 보류. 구현·정책을 임의 확정하지 않음.
- `POST-MVP`: 제품 방향에는 포함되지만 MVP 제외.
- `PROPOSAL`: 기술 예시/추천일 뿐 명시 승인 전 추가 확정 아님.
- 충돌 시 최신 사용자 직접 지시 > 이전 직접 지시 > 권장 초안 > 기술 제안. 보안·법률 및 도구 권한은 별도 준수.

## 보류 및 별도 검토

- **O01 OFFLINE — ON-HOLD**: 오프라인 상태에서 완료/취소 등의 *쓰기* 동작 허용 여부, 로컬 큐·충돌 처리 및 데이터 보존 범위는 확정되지 않았다. 개발 에이전트가 스스로 정하면 안 된다.
- **O02 소셜 공급자**: 제공자 최소화만 확정. Google/Apple/Kakao 조합·출시 규정은 착수 전 결정·검증.
- **O03 시간대 경계**: 공간 시간대는 확정, DST 부재·중복 시각/알림용 개인 시간대 세부는 권장 초안으로 검증 필요.
- **O04 백업 실효성**: Supabase Free 제약, 실제 저장 위치·암호화 키 관리·Auth 복원 범위는 착수 시 공식 문서·운영 환경 검증.
- **O05 대리 완료 정정 요청 UX**: 요청 수락·거절 및 이력 세부 상태는 RECOMMENDED-DRAFT.
- **O06 최종 앱 이름·브랜드**: 미정. 이미지에 표시된 '같이, 더 가볍게'는 참고 디자인의 문구이며 앱 이름 확정이 아님.
- **O07 일정**: 12~18주/주 15~20시간 가정은 과거 계획의 추정치, 납기 약속 아님.
- **O08 외부 Notion**: 카카오톡의 링크가 존재하나 문서 내용은 이 패키지에서 읽거나 검증하지 않았으므로 포함했다고 주장하지 말 것.

## 변경 통제

1. 권장 초안에 대한 수정은 의사결정 로그 변경 후 관련 PRD·상태 전이·테스트까지 동시 갱신.
2. 직접 확정 정책의 변경은 사용자 승인 필요.
3. 법·보안상 구현 불가 정책 발견 시 임의 우회 대신 사유·대안 보고.
4. MVP 제외 기능을 에이전트가 임의 추가하지 말 것.
