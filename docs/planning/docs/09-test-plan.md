# 품질 전략 및 테스트 매트릭스

## 완료 판정

상태는 `설계됨 → 구현됨 → 자동 테스트 통과 → 실행 확인 → 독립 검증 완료`로 구분. 실제 테스트하지 않은 항목은 '검증 불가/차단'으로 남기고 완료 처리 금지. CI 성공만으로 실제 iOS/Android 사용성을 증명하지 않는다.

## 자동 검증 레이어

- 타입·정적 검사: TypeScript, 린트, 포맷, dependency audit.
- 단위: 달력 반복/월말/윤년/규칙 버전, 교대 순서, DND/재알림 결정.
- DB 통합: RLS 교차 공간 접근, 멱등 요청, 상태 전이, 동시 완료, 취소 충돌, 고유 회차 생성.
- API 통합: 인증·초대 만료·도움 수락·프로필 탈퇴.
- 모바일 E2E: 최초 로그인/온보딩/공간 전환/완료/캘린더/반응.
- 네트워크: 실시간 누락/재연결, 오류·재시도, 다중 기기. **오프라인 변경 기능 자체는 아직 미확정.**

## 테스트 매트릭스

| ID | 시나리오 | 필수 기대값 |
|---|---|---|
| T01 | 같은 회차 A/B 동시 완료 | 서버 최초 1건만 확정, 나머지 안전하게 최신화 |
| T02 | 완료-건너뛰기 경합 | 유효한 한 상태만 확정 |
| T03 | 취소 후 다음 회차 완료됨 | 자동 데이터 삭제 금지·충돌 안내 |
| T04 | 고정 회차 장기 미완료 | 미래 회차 생성, 과거 기록 보존, 홈 현재 우선 |
| T05 | 완료 후 N일, 건너뛰기 | 건너뛴 날 기준 새 간격, 완료로 미집계 |
| T06 | 수동 동일 루틴 하루 세 번 | 독립 회차·순차 교대·이중 요청 방지 |
| T07 | 주기 변경/개별 수정 미래 회차 | 개별 수정 보존, 나머지 미래만 재계산 |
| T08 | 월말/윤년/시간대 | 존재하지 않는 일은 말일 보정, 공간 날짜 일관 |
| T09 | 다른 공간 ID를 사용한 조회/수정 | RLS 및 서버 검증으로 모두 차단 |
| T10 | 만료 초대/중복 초대 수락 | 중복 멤버십 생성 없음 |
| T11 | 도움 요청·수락 경합 | 담당자 전가 전 수락 필수 |
| T12 | 마지막 관리자 탈퇴 | 무관리자 공간 상태 방지 |
| T13 | 두 기기·중복 Cron | 논리 알림 1개, 기기별 발송 제어 |
| T14 | 완료 후 예정 알림 시각 도달 | 서버 검증 후 불필요한 알림 취소 |
| T15 | 푸시 제공자 오류/무효 토큰 | 유한 재시도/비활성화/상태 구분 |
| T16 | 재연결·공간 전환 | 올바른 공간 최신 DB 재조회, 잘못된 캐시 제거 |
| T17 | 계정 삭제·복원 | 계정/개인정보 정리·공유 이력 정책·복원 후 재삭제 검증 |
| T18 | 백업 복원 | 별도 테스트 환경에 성공적으로 복원·무결성 확인 |
| T19 | 라이트/다크·큰 글꼴·스크린리더 | 핵심 흐름 접근 가능 |
| T20 | 실제 iOS/Android 기기 | 로그인·알림·완료·다크/제스처 검증 |

## 내부 베타

4~8명/약 14일, 개인 사용자와 2명 이상 공간 포함. 검증할 질문: 첫 루틴 완료까지의 마찰, 교대/요청의 이해, 알림 피로, 실시간 신뢰성, 재사용 의도. 사전에 사용자의 테스트 동의/데이터 삭제 안내. 베타 중 치명적 보안·데이터 손실 결함 발생 시 확장 중단.

## 증거

각 작업 보고에는 명령, 실행 환경, 실제 결과(로그·스크린샷·테스트 보고), 실패/미검증, 관련 PR 또는 커밋을 연결. 검증이 불가능하면 이유와 대체 검사까지 기록.
