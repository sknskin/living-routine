## 수행 지침

1. CLI·OS·브랜치·기존 변경 및 관련 문서를 먼저 확인한다.
2. 구현 대상의 현재 상태와 근거를 제시하고, 불확실한 정책은 임의로 정하지 않는다.
3. 기능의 DB·서버·UI·테스트 경계를 확인한다.
4. 독립 부분만 병렬화하고 충돌 가능 파일/DB는 단일 소유자가 수정한다.
5. 구현 후 실제 테스트·실행 확인·독립 검증을 수행한다.
6. 차단 또는 도구 부족 시 검증되지 않은 부분을 분리하여 보고한다.
